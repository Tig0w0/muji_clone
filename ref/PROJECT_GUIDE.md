### 1. 정적 HTML 데이터를 React 컴포넌트로 이식하기 (기획전 상세페이지)

**[상황]**
무인양품과 같은 실제 이커머스 사이트에서는 기획전이나 상품 상세 설명 페이지의 디자인이 매우 자주, 화려하게 바뀝니다. 프론트엔드 개발자가 매번 컴포넌트를 새로 짜는 것은 비효율적이므로, 서버(CMS)에서 **완성된 거대한 HTML/CSS 코드를 통째로 데이터(JSON)에 담아 넘겨주는 방식**을 주로 사용합니다.

**[작업 내용]**
원본 JSON(`04.json`) 파일 안에 문자열로 꽁꽁 숨겨져 있던 순수 HTML 코드를 추출하여, 우리 리액트 프로젝트의 독립된 컴포넌트(`PlanDetail.js`)로 예쁘게 이식하고 페이지 라우팅(`/plan/view/:id`)을 연결했습니다.

**[리액트 문법 변환 (HTML ➡️ JSX) 핵심 포인트]**
리액트는 순수 HTML이 아니라 자바스크립트 기반의 **JSX**라는 문법을 사용합니다. 따라서 추출한 HTML을 복붙만 하면 에러가 납니다! 아래 4가지 핵심 규칙에 맞춰 변환하는 작업을 거쳤습니다.

1. **`class` ➡️ `className`** 
   - 자바스크립트의 클래스(class) 예약어와 충돌하지 않도록 리액트에서는 무조건 `className`으로 적어줘야 합니다.
2. **단일 태그 닫기 (`<img />`, `<br />`, `<input />`)**
   - HTML에서는 `<br>` 처럼 닫는 태그가 없어도 브라우저가 알아서 렌더링해주지만, 매우 엄격한 JSX 문법에서는 반드시 끝에 슬래시(`/`)를 넣어 태그가 끝났음을 알려주어야 에러가 나지 않습니다.
3. **인라인 스타일 변환 (`style="..."` ➡️ `style={{...}}`)**
   - JSX에서 인라인 스타일은 일반 텍스트가 아닌 **자바스크립트 객체** 형태로 들어가며, 속성명은 카멜케이스(camelCase)를 사용해야 합니다. (예: `background-color` 👉 `backgroundColor`)
4. **`for` ➡️ `htmlFor`**
   - `<label>` 태그의 `for` 속성 역시 자바스크립트 반복문인 `for`와 겹치므로 `htmlFor`로 변환해야 합니다.

> "실제 이커머스 실무에서 자주 쓰이는 방식(서버에서 정적 HTML 데이터를 받아 렌더링하는 CMS 방식)을 경험해 보았습니다. 방대한 HTML 문자열 데이터를 단순히 띄우는 데 그치지 않고, 직접 리액트 컴포넌트로 분리하고 **JSX 문법(className, self-closing tag 등)에 맞춰 엄격하게 마이그레이션(Migration)하는 작업**을 수행했습니다. 이 과정을 통해 JSX 문법의 원리와 특징을 완벽하게 내재화할 수 있었습니다."

### 2. 브라우저 저장소(`localStorage`)를 활용한 상태 유지 (최근 본 상품 기능)

**[상황]**
사용자가 상품 상세 페이지를 조회한 기록을 남겨, 메인 페이지나 다른 페이지로 이동하더라도 "내가 가장 최근에 본 상품"을 화면 하단 플로팅 버튼에 띄워주고 싶습니다. 하지만 리액트의 `useState` 상태값은 새로고침을 하거나 탭을 닫으면 전부 초기화되어 날아가는 문제가 있습니다.

**[작업 내용]**
상태를 브라우저에 영구적으로(혹은 직접 지우기 전까지) 보관할 수 있는 Web Storage API인 **`localStorage`**를 활용하여 기능을 구현했습니다.

**[구현의 핵심 포인트]**
1. **데이터 쓰기 (상세 페이지 진입 시)**
   - `ProductDetail.js` 컴포넌트가 화면에 마운트(렌더링)될 때, `useEffect` 훅 내부에서 `localStorage.setItem('recentProductId', 상품ID)`를 호출하여 현재 상품의 고유 ID를 브라우저 저장소에 콕 박아둡니다.
2. **데이터 읽기 (푸터 플로팅 버튼 렌더링 시)**
   - 모든 페이지의 하단에 고정되어 있는 `Footer.js` 컴포넌트에서 렌더링 시 `localStorage.getItem('recentProductId')`를 호출하여 값을 읽어옵니다.
   - 읽어온 ID를 바탕으로 상품의 원본 데이터(이름, 썸네일 이미지 등)를 조회한 뒤 화면에 뿌려줍니다.
3. **상태 동기화 (라우터 감지)**
   - 만약 사용자가 A상품에서 B상품으로 페이지를 이동했을 때, 푸터 컴포넌트가 이를 알아채지 못하면 여전히 A상품을 띄우게 됩니다.
   - 이를 해결하기 위해 `react-router-dom`의 **`useLocation`** 훅을 `Footer.js`에 선언했습니다. 경로가 바뀔 때마다 리액트가 이를 감지하고 푸터를 리렌더링하게 하여, 플로팅 버튼 이미지가 즉각적으로 최신화되도록 구성했습니다.
